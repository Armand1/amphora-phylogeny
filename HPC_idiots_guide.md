# An Idiot's Guide to Running a RevBayes Phylogeny on the HPC

Everything we did to get the three-clade amphora tree running on Imperial's
cx3 cluster, in order, with the actual commands. Follow it top to bottom next
time and you won't need to remember any of it.

The idea in one sentence: **build the data + model on your Mac → push it to a
GitHub repo → clone that repo onto the HPC → submit one job → wait → pull the
results back.** The HPC never touches your Mac directly; GitHub is the go-between.

---

## Step 0 — What you need once (already done, for reference)

- **A GitHub account** (`Armand1`) and the `gh` command-line tool, logged in:
  ```bash
  gh auth status          # should say "Logged in to github.com account Armand1"
  ```
- **An HPC account** (`amleroi`) and the ability to log in:
  ```bash
  ssh amleroi@login.cx3.hpc.imperial.ac.uk
  ```
- **RevBayes built on the HPC.** The submission script expects the binary at
  `$HOME/revbayes/projects/cmake/build-mpi/rb-mpi`. If that file doesn't exist
  under your account, that's the one thing you must sort out first (build it,
  or point at a shared copy).

---

## Step 1 — Build the model + data (on the Mac)

RevBayes needs two data files and a few model scripts. For this tree they live
in `~/Documents/Amphora_phylogeny/three_clade_tree/`:

| file | what it is |
|---|---|
| `data/mini_character.nex` | the shape data: 39 pots × 10 PCs (NEXUS continuous) |
| `data/mini_taxa.tsv` | each pot's age range (min/max years BP) |
| `master_script.Rev` | the top-level model: reads data, runs the MCMC |
| `scripts/FBD.Rev`, `strict_clock.Rev`, `simple_BM.Rev` | the model pieces |
| `submit_hpc.pbs` | the HPC job script (see Step 4) |

The data files were generated by a script, so they're reproducible:
```bash
cd ~/Documents/Amphora_phylogeny/three_clade_tree
Rscript make_revbayes_data.R        # writes data/mini_character.nex + data/mini_taxa.tsv
```

---

## Step 2 — Put it in a GitHub repo (on the Mac, once per tree)

The HPC pulls the model by cloning a GitHub repo, so we make one:
```bash
cd ~/Documents/Amphora_phylogeny/three_clade_tree
git init                            # turn this folder into a git repo
git add -A                          # stage everything
git commit -m "first commit"        # save a snapshot
gh repo create Armand1/amphora-phylogeny --public --source=. --remote=origin --push
```
That last line creates the repo on GitHub **and** uploads everything.
Repo is now live at <https://github.com/Armand1/amphora-phylogeny>.

**Whenever you change a file afterwards** (e.g. regenerate the data, edit the
model), push the change so the HPC can pull it:
```bash
git add -A
git commit -m "what I changed"
git push
```

---

## Step 3 — Get the model onto the HPC (on the HPC)

Log in, go to your GitHub folder, and clone the repo:
```bash
ssh amleroi@login.cx3.hpc.imperial.ac.uk
cd ~/GitHub
git clone https://github.com/Armand1/amphora-phylogeny.git
```
You now have `~/GitHub/amphora-phylogeny/` on the cluster.

**If you changed something on the Mac and pushed it**, update the HPC copy with:
```bash
cd ~/GitHub/amphora-phylogeny
git pull
```

---

## Step 4 — The job script (what `submit_hpc.pbs` does)

You don't run RevBayes directly on the login node — you hand a *job script* to
the scheduler (`qsub`), which finds a free compute node and runs it there. Ours
(`submit_hpc.pbs`) does, in plain English:

- asks for **1 node, 16 CPUs, 20 GB RAM, up to 24 h** (the `#PBS` lines);
- `cd`s to `~/GitHub` and makes an `output/` folder;
- checks the `rb-mpi` binary actually exists (fails loudly if not);
- loads the required software modules (`OpenMPI`, `GCC`, …);
- runs RevBayes across 16 CPUs on `master_script.Rev`, sending all output to
  `output/logfile.log`.

The 16 CPUs matter because the model runs `mcmcmc(nchains=5, nruns=3)` = 15
parallel chains; 16 ranks gives each chain a core.

---

## Step 5 — Submit the job (on the HPC)

```bash
cd ~/GitHub
qsub amphora-phylogeny/submit_hpc.pbs
```
This prints a **job ID** like `3407134.pbs-7`. That means it's queued.

---

## Step 6 — Watch it (on the HPC)

```bash
qstat -u amleroi        # your jobs. S column: Q = queued, R = running, gone = done/failed
```
Once it's `R` (running), watch the live log:
```bash
tail -f ~/GitHub/amphora-phylogeny/output/logfile.log     # Ctrl-C to stop watching
```
- Starts with `INFO:Starting …` then RevBayes chatter → it's working.
- Says `ERROR: RevBayes not found …` → the `rb-mpi` path is wrong (Step 0).
- A tiny tree like this finishes in minutes-to-an-hour once it actually starts;
  queue waits can be longer than the run itself.

When the job disappears from `qstat`, it's finished (or died) — check the log.

---

## Step 7 — Get the results back (on the Mac)

The run produces, in `~/GitHub/amphora-phylogeny/output/` on the HPC:

| file | what it is |
|---|---|
| `simple_run_mcc.tree` | **the tree** (maximum-clade-credibility summary) |
| `simple_run*.trees` | every sampled tree (the posterior) |
| `simple_run.log` | all the numbers (rates, ages) — open in **Tracer** |
| `logfile.log` | the run's console output / errors |

Copy them down to the Mac with `scp` (run this **on the Mac**, not the HPC):
```bash
scp -r amleroi@login.cx3.hpc.imperial.ac.uk:'~/GitHub/amphora-phylogeny/output' \
      ~/Documents/Amphora_phylogeny/three_clade_tree/hpc_output
```

Then plot the tree by pointing the R notebook at that folder
(`simpletree_plots.Rmd`, set `params$dir`), and open `simple_run.log` in Tracer
to check the run mixed properly (ESS > 200, PSRF ≈ 1).

## The whole thing, condensed

```bash
# --- Mac: build + publish ---
cd ~/Documents/Amphora_phylogeny/three_clade_tree
Rscript make_revbayes_data.R
git add -A && git commit -m "update" && git push

# --- HPC: pull + run ---
ssh amleroi@login.cx3.hpc.imperial.ac.uk
cd ~/GitHub/amphora-phylogeny && git pull      # (or git clone … the first time)
cd ~/GitHub && qsub amphora-phylogeny/submit_hpc.pbs
qstat -u amleroi                               # wait for R, then gone

# --- Mac: retrieve ---
scp -r amleroi@login.cx3.hpc.imperial.ac.uk:'~/GitHub/amphora-phylogeny/output' ./hpc_output
```

## When something goes wrong

| symptom | likely cause | fix |
|---|---|---|
| job vanishes instantly, log says `ERROR: RevBayes not found` | `rb-mpi` not under your account | build RevBayes, or point `PROGRAM=` in `submit_hpc.pbs` at a valid binary |
| stuck on `Q` for ages | cluster busy | just wait; it's normal |
| RevBayes errors about a file path | wrong `BASE` in `master_script.Rev` | `BASE` must match the folder prefix used in the `.pbs` (`amphora-phylogeny`) |
| root date jammed at a round number | `origin_time` prior ceiling too low | raise the ceiling in `scripts/FBD.Rev` (we set it to 4000) |
| tree looks like noise / dates too old | too many low-variance PCs fed to one BM rate | use fewer PCs (`trait <- 1:N` in `master_script.Rev`) |
```
